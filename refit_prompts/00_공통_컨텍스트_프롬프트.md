# [공통 컨텍스트] RE-FIT — 앱·웹 개발 전 반드시 읽을 것

> 사용법: 앱 프롬프트(01) 또는 웹 프롬프트(02)를 실행하기 전에 이 문서를 먼저 붙여넣는다.
> 이 문서의 상수·정의·금지사항은 협상 대상이 아니다. 임의로 바꾸지 말고, 바꿔야 한다고 판단되면 먼저 물어볼 것.

---

## 1. 제품이 무엇인가

**RE-FIT**은 완전마비 환자의 손 재활을 위한 FES(기능적 전기자극) 기반 훈련 시스템이다. 두 개의 클라이언트로 구성된다.

- **RE-FIT Play** — Flutter 앱. 환자 본인이 쓴다. 게임을 하며 훈련한다.
- **RE-FIT Care** — 웹. 치료사·관리자가 쓴다. 환자 기록을 조회하고 진행 중인 세션을 실시간으로 본다.

하드웨어는 ESP32 기반 컨트롤러다. EMG 센서(MyoWare 2.0)로 근전도를 1kHz로 읽고, 전기자극기(오므론 HV-F022-V)의 전원을 제어해 FES를 준다. 앱과는 BLE로 통신한다.

### 핵심 동작 원리 (이걸 이해 못 하면 코드가 전부 틀린다)

환자는 **완전마비**라 스스로 손을 쥘 수 없다. 손을 쥐게 하는 것은 FES 자극이다. 앱이 하는 일은 그 자극으로 **실제 수축이 일어났는지 EMG로 확인하고, 그 순간을 화면과 시간적으로 일치시키는 것**이다.

신경가소성은 아래 셋이 같은 시점에 겹칠 때 발생한다.

1. 운동 의도 — 화면의 손이 쥐어지는 걸 보며 "쥔다"고 생각하는 순간
2. 실제 움직임 — FES가 근육을 수축시키는 순간
3. 감각 되먹임 — 손이 쥐어졌다는 고유수용감각

**따라서 이 시스템의 기술적 핵심은 게임의 재미가 아니라 타이밍 정확도다.** 화면 큐가 자극보다 늦게 나오면 훈련 효과가 사라진다. 타이밍을 희생하는 최적화는 어떤 이유로도 하지 않는다.

## 2. 신호 파이프라인 명세

### 2.1 입력 데이터

BLE로 들어오는 것은 **1kHz 원시 ADC 샘플뿐**이다. 오프라인 CSV와 동일한 형식이다.

```csv
Time(ms),Raw_ADC
0,1851
1,1831
```

- 샘플레이트 1000 Hz
- ADC 12bit 상당, DC offset은 1800~1900대 (기기·세션마다 다름)
- **자극 트리거 신호는 오지 않는다.** 펌웨어가 보내주지 못한다. 앱이 raw에서 직접 찾아야 한다.

### 2.2 버스트 구조 (실측)

FES는 주기적 버스트로 나간다.

| 항목 | 값 |
|---|---|
| 자극 ON 구간 | 591 ms |
| 자극 OFF 구간 | 1027 ms |
| **총 주기** | **1618 ms** |
| 버스트 내 펄스 주파수 | 32 Hz |
| 분당 반복 | 약 37회 |
| 세션당 버스트 수 | 약 340개 (중앙 9.3분) |

이 값들은 88세션 29,611버스트 실측에서 나왔다. 사전값으로 쓰되, 세션마다 실제 값을 추정해 갱신한다.

### 2.3 처리 단계

```
raw ADC (1kHz)
  → [A] DC offset 자동 캘리브
  → [B] 자극 아티팩트 검출 → 주기 추정 → 위상 고정
  → [C] 버스트 분할
  → [D] 에폭별 영점보정
  → [E] 5–15ms 창에서 M-wave p2p 산출 (펄스별)
  → [F] 버스트당 중앙값 1개로 집계
  → [G] Hampel 필터 (k=7, 3σ)
  → [H] 적응형 레벨 구간 추적 + A_ref running-peak
  → [I] 인과 EMA → 피로도%
  → [J] 수축 성공 판정 (open/closed)
```

**[A] DC offset 자동 캘리브**
세션 시작 직후 무자극 1–2초 구간의 평균값을 DC offset으로 삼는다. 하드코딩 금지(기존 펌웨어의 `DC_OFFSET = 1862` 하드코딩이 오류 원인이었다).

**[B] 자극 검출·주기 추정·위상 고정**
```
1. 절대값(신호 − DC) > 임계 인 샘플을 후보로 추출
   - 임계는 적응형: 세션 초기 무자극 구간 noise RMS의 배수로 설정
   - 고정 임계 1000 금지 (아티팩트 진폭대 900~1300 하단에 걸려 버스트 통째 누락됨)
2. 불응기(refractory) 기반 그룹화 후 각 그룹의 argmax를 자극 시점으로 확정
3. 확정된 시점들의 간격에 자기상관 적용 → 주기 추정 (사전값 1618ms 근방 탐색)
4. 첫 자극 시점 기준으로 UI 타임라인을 phase-lock
5. 매 N버스트마다 실제 검출 시점으로 위상 재정렬 (드리프트 보정)
```
scipy 없이 numpy만으로 구현 가능한 방식이다(오프라인 파이프라인이 동일하게 구현되어 있다).

**[D] 에폭별 영점보정 — 중요**
각 자극 에폭마다 개별적으로 영점을 잡는다. **자극 직전 구간을 영점 기준으로 쓰면 안 된다.** 실측에서 자극 직전 5샘플이 M-wave 피크의 중앙 20.2% 크기로 오염되어 있었고, 88세션 중 74세션이 10%를 넘었다. 이 오염을 방치하면 진폭이 계통적으로 왜곡된다.

**[E] M-wave 창**
자극 시점(onset = 0ms) 기준 **5–15ms** 구간. 이 구간에서 peak-to-peak을 구한다. 1kHz이므로 샘플 10개뿐이다. 절대값보다 상대 변화로 해석해야 한다.

**[G] Hampel 필터**
윈도우 k=7, 임계 3σ. 전극 순간 접촉 불량으로 생기는 글리치를 제거한다. 실측 사례에서 이 필터 하나로 최대 피로도가 52%(글리치)에서 27.4%(실제)로 정정됐다. **생략하면 피로도가 과대평가된다.**

**[H] 적응형 레벨 구간 + A_ref**
세션 중 접촉·자세 변화로 진폭 레벨이 계단식으로 바뀐다(실측 세션당 평균 4.1회). 이 계단을 피로로 세면 안 된다.
```
- 진행 중 레벨 시프트를 온라인으로 감지 (최근 W버스트 중앙값이 현재 구간 기준선 대비
  임계 이상 벗어난 상태가 M버스트 지속되면 새 구간 시작)
- A_ref = 현재 레벨 구간의 running-peak, post-peak only (피크 이후만 피로로 카운트)
- W, M, 임계는 P0에서 실측 튜닝 대상. 코드에서 상수로 분리해 둘 것
```

**[I] 피로도**
```
fatigue% = clamp( 100 × (1 − EMA(p2p_burst) / A_ref_현재구간), 0, 100 )
워밍업 구간에서는 0 (또는 "준비 중")
```

**[J] 수축 성공 판정**
```
contraction_ok = (p2p_burst >= A_ref_현재구간 × K)     // K는 0.3 근방, 튜닝 대상
closed(쥠)  = 자극 ON 구간 && contraction_ok
open(폄)    = 자극 OFF 구간
실패        = 자극은 나갔으나 contraction_ok == false  → 전극 접촉 불량 또는 강도 부족
```

### 2.4 신뢰도 게이팅

| 조건 | 처리 |
|---|---|
| events/burst ≥ 10 AND 검출률 ≥ 50% | 정상 |
| events/burst < 10 | 피로도 판정 보류, UI에 "센서 확인" 표시 |
| 검출 실패 30초 지속 | 자극 중단, 부착 체크로 이동 |

실측 88세션 중 58세션만 이 기준을 통과했다. **게이팅을 빼면 3분의 1은 틀린 값을 보여주게 된다.**

## 3. 하드 제약 (위반 금지)

1. **자극 직전 구간을 영점 기준으로 쓰지 않는다.** (2.3 [D])
2. **MDF·주파수 지표를 피로 판정에 쓰지 않는다.** 무부하 FES에서는 MDF가 자극 하모닉(32/64/96Hz)과 혼동되어 무의미하다. 피로는 진폭에 있다(세션 내 분리력 RMS 0.51 / p2p 0.44 vs MDF 0.008).
3. **RMS 상승을 피로로 판정하지 않는다.** 그건 자발적 수축의 피로 논리다. FES 유발 반응의 피로는 **진폭 감소**다. 방향이 반대다.
4. **SPC(관리도) 고정 baseline을 쓰지 않는다.** 초기 몇 표본으로 baseline을 고정하면 초반 전위증강(potentiation) 구간에 걸려 이후 전 구간이 피로로 오판된다.
5. **게이지 급등을 피로 급증으로 처리하지 않는다.** 32초 내 30%p 이상 급등은 실측 13/58 세션에서 나타났고 대부분 전극·자세 변화다. **"센서 점검 안내"로 분기한다.**
6. **환자 간 절대 피로% 비교·순위를 만들지 않는다.** 계산 방법에 따라 값이 두 배 이상 갈리고(전역 44% vs 적응형 19%), 피험자별 중앙값도 11~66%로 개인차가 피로 차이보다 크다.
7. **UI 타이밍을 희생하지 않는다.** 렌더링 부하가 커지면 신호 처리가 아니라 시각 효과를 줄인다.
8. **원격 중단은 안전 기능의 1차가 될 수 없다.** 로컬 자동 종료가 항상 1차이고, 원격 중단은 보조다.

## 6. DB 스키마 (Supabase / Postgres)

```sql
patients(id, anon_code, display_name, birth_year, affected_side, paralysis_type, created_at)
therapists(id, name, email, org_id, created_at)
invite_codes(code PK, therapist_id, expires_at, used_by_patient_id, used_at, created_at)
care_relations(therapist_id, patient_id, granted_at, PRIMARY KEY(therapist_id, patient_id))
devices(id, serial, firmware_version, assigned_patient_id, created_at)
intensity_profiles(id, patient_id, level, valid_from, events_per_burst_at_set)

sessions(
  id, patient_id, device_id, started_at, ended_at, duration_s,
  game_id, stage_id, intensity_level,
  end_reason,                          -- 5장 enum
  rep_count, success_rate,
  max_fatigue, end_fatigue, onset_s,   -- 전부 적응형 기준
  burst_count, detect_rate, events_per_burst_median,
  level_change_count, reliability_grade,   -- A/B/C
  stim_period_ms, app_version, fw_version
)

session_live(                          -- 라이브 뷰용, 세션당 1행 upsert
  session_id PK, updated_at, elapsed_s, rep_count,
  fatigue, success_rate_50, signal_quality, state
)

session_series(                        -- 버스트 단위
  session_id, t_s, p2p, fatigue, contraction_ok, valid
)

session_events(
  session_id, t_s, type, actor, payload
)                                      -- type: level_change | signal_warning |
                                       --       user_pause | remote_stop | stim_off
remote_commands(
  id, session_id, issued_by, command, issued_at,
  acked_at, executed_at, status         -- sent | acked | executed | failed
)
```

`sessions` 한 행이 웹의 목록·요약 화면 전부를 커버해야 한다. `session_series`는 리포트 그래프에서만 읽는다.

## 7. 용어집

| 용어 | 뜻 |
|---|---|
| M-wave | FES 자극에 의해 유발된 복합근활동전위. 자발적 EMG가 아니다 |
| 버스트 | 자극 1회분(ON 591ms). 게임의 "쥠/폄 1회"와 1:1 대응 |
| events/burst | 한 버스트 안에서 검출된 M-wave 개수. 신뢰도 지표 |
| A_ref | 피로 0%의 기준 진폭. 현재 레벨 구간의 running-peak |
| 레벨 구간 | 접촉·자세 변화로 진폭 기준선이 바뀌는 구간. 세션당 평균 4.1개 |
| 전위증강(potentiation) | 세션 초반 진폭이 오히려 커지는 현상. **피로가 아니다** |
| 적응형 기준 | 레벨 구간별 A_ref를 쓰는 방식. 이 프로젝트의 공식 기준 |
| 전역 기준 | 세션 전체 단일 A_ref. 참고용, 자동 종료에 쓰지 않는다 |
| 큐(cue) | 화면에서 "지금 쥔다"를 알리는 시각 신호. 자극보다 300ms 선행 |

## 8. 검증 자료

오프라인 원시 데이터가 `emgfes-data/subject_*/raw_*.csv` 에 90개 있다(88세션 처리 성공). 신호 엔진을 구현하면 **반드시 이 파일들로 회귀 테스트를 작성**하고, 기존 Python 파이프라인(`fes_fatigue_regression.py`)의 출력과 대조한다.

| 검증 항목 | 기대 |
|---|---|
| 자극 주기 추정 | 대부분 세션에서 1618ms ± 소폭 |
| 버스트 수 | 세션당 중앙 337개 |
| 신뢰도 통과 세션 | 88개 중 58개 |
| 적응형 임계 검출 | 58개 중 47개 (전역은 52개) |
| 세션 길이 | 중앙 9.3분 |

숫자가 이 범위에서 크게 벗어나면 구현이 틀린 것이다. 임의로 파라미터를 맞춰 숫자를 억지로 끼워 넣지 말고, 어디가 다른지 보고할 것.
