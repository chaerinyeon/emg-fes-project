# RE-FIT — 전체 메뉴 구조 설계

FES 유발 근수축으로 게임을 수행하고, EMG 기반 근피로 분석으로 실시간 피드백을
주는 재활 앱. 대상은 **완전마비 환자**이며 한 손으로 조작한다.

이 문서는 화면 계층·역할·UI 요소를 정의한다. 신호 처리 규칙은
`00_공통_컨텍스트`, 세션 상태 전이는 `lib/session/session_controller.dart` 가
정본이다.

---

## 0. 최상위 구조

```
RE-FIT Play
│
├─ [최초 진입] 환자 선택                       ← 탭 바깥. 환자가 없거나 미선택일 때만.
│   ├─ 환자 리스트 (카드)
│   └─ ＋ 환자 추가 ─→ 환자 편집 시트
│
└─ 하단 네비게이션 (4탭)
    ├─ ① 홈        오늘의 상태 · 빠른 시작
    ├─ ② 운동      Setup → Game → Result (단방향)
    ├─ ③ 기록      날짜별 · 그래프 · 원시 데이터
    └─ ④ 설정      기기 · 강도 · 환자 · 앱 정보
```

**AppBar 우측 상단에 `TEST` 버튼이 모든 탭에서 상시 노출된다.**
BLE 연결 없이 동작하며, UI·센서·자극기를 단독으로 확인한다(§6).

### 탭이 사라지는 구간

운동이 **시작된 뒤에는 하단 탭이 숨는다.** `Setup → Game → Result` 는 단방향
흐름이고, 중간에 다른 탭으로 빠져나가면 자극이 켜진 채 화면만 바뀐다.
결과 화면에서 `마치기` 를 눌러야 탭이 돌아온다.

## 1. 홈 (Dashboard)

역할: **오늘 무엇을 할지 3초 안에 알려 준다.** 정보를 늘어놓는 화면이 아니다.

```
① 홈
├─ AppBar
│   ├─ (좌) 선택된 환자 이름
│   └─ (우) [TEST]
│
├─ 환자 카드                       ← 탭하면 환자 선택 화면
│   ├─ 이름 · 나이
│   ├─ 마비 유형 뱃지 (완전마비 / 불완전마비)
│   └─ 누적 세션 수 · 마지막 운동일
│
├─ 오늘의 상태 요약
│   ├─ 피로도 상태 칩   좋음 · 주의 · 피로     ← 숫자 없음. 3단계 상태만.
│   ├─ 오늘 운동 여부   "오늘 1회 완료" / "아직 안 했어요"
│   └─ 데이터 없을 때   "오늘은 아직 기록이 없어요"
│
├─ 최근 운동 결과 요약 카드
│   ├─ 날짜 · 운동 시간 (예: 9분 18초)
│   ├─ 쥔 횟수 (예: 340번)
│   └─ 마무리 문구 ("오늘 몫을 다 했어요")
│
└─ [운동 시작]  ← 큰 버튼. 누르면 ②운동 탭의 사전 세팅으로.
```

**규칙**
- 피로도는 **퍼센트를 쓰지 않는다.** 좋음/주의/피로 3단계 상태로만 말한다.
- 색은 `좋음=민트`, `주의=노랑`, `피로=호박`. **빨강은 쓰지 않는다** —
  빨강은 기기 문제 전용이고, 피로에 빨강을 쓰면 환자의 몸 상태를
  경고로 만든다.
- 환자 간 비교·순위를 표시하지 않는다(하드 제약 6).

## 2. 환자 선택 및 등록

접근 경로: 최초 진입 · 홈의 환자 카드 · 설정 > 환자 관리.

```
환자 선택
├─ 환자 리스트 (카드)
│   ├─ 이름 · 나이 · 마비 유형 뱃지
│   ├─ 누적 세션 수 · 마지막 운동일
│   └─ (길게 누르기) 수정 / 삭제
└─ ＋ 환자 추가

환자 추가 / 수정 시트
├─ 이름            (텍스트)
├─ 나이            (숫자)
├─ 마비 유형        (토글 2개 중 택1)
│   ├─ 완전마비
│   └─ 불완전마비
└─ [저장]
```

### 마비 유형은 라벨이 아니라 **분석 경로를 바꾸는 스위치**다

| 유형 | 피로 판정에 쓰는 지표 |
|---|---|
| 완전마비 | **M-wave 진폭만.** 자발 EMG가 없어 RMS·MDF는 자극 하모닉과 구분되지 않는다. |
| 불완전마비 | M-wave 진폭 + RMS · MDF 보조 |

이 값이 틀리면 피로 판정 자체가 틀린다. 그래서 저장 시 필수 항목이다.

## 3. 운동 (게임) 탭

`Setup → Game → Result` 단방향. 상단에 3점 단계 인디케이터.

### 3-1. 사전 세팅

```
③-1 사전 세팅
├─ AppBar  [TEST]
│
├─ 장치 연결
│   ├─ BLE 연결 상태     연결됨 / 찾는 중 / 연결 안 됨 (+ 원인)
│   └─ [장치 연결]        실패해도 화면에 남고 다음 할 일을 말한다
│
├─ 부착 상태 확인          ← 각 항목에 부착 위치 그림
│   ├─ EMG 전극    팔 안쪽, 손목에서 손가락 세 마디 위
│   ├─ 자극 패드    전극 아래쪽, 두 장이 닿지 않게
│   ├─ 기기        배터리와 연결 상태
│   └─ [확인 시작]  → 실제 신호로 자동 판정 (체크 / 다시)
│
├─ 강도 설정
│   ├─ 슬라이더 1 ─────●───── 10
│   ├─ 안내: "기기 다이얼을 이 단계에 맞춰 주세요"
│   ├─ [이 세기로 측정]   자극을 걸어 보고 신호가 잡히는지 확인
│   └─ 결과: "신호가 잘 잡혀요" / "신호가 약해요"   ← 수치 비노출
│
├─ [테스트]               자극 없이 UI·센서·화면만 확인 (BLE 불필요)
│
└─ [운동 시작]            ← 부착 3항목 통과 + 강도 측정 통과해야 활성
```

**강도 슬라이더의 정직한 정의**

실제 자극 세기는 오므론 HV-F022-V의 **물리 다이얼**이 정한다. 앱이 슬라이더로
기기 출력을 바꿀 수 없다. 그래서 슬라이더는

1. 지금 다이얼이 몇 단계인지 **기록**하고,
2. 그 단계에서 근육 반응이 잡히는지 **측정**한다.

측정은 `events/burst ≥ 10` 을 본다. 목표는 이 조건을 만족하는 **최소** 강도다 —
세면 셀수록 좋은 게 아니다. 여기서 정한 값이 **그날의 상한**이 되고,
세션 중에는 **내리는 것만** 가능하다.

**게이트**

부착 3항목과 강도 측정을 통과하지 않으면 `운동 시작` 이 눌리지 않는다.
이건 버튼 비활성화가 아니라 **상태머신 전이**로 막는다 — 화면 라우팅이
세션 상태와 1:1이라 "건너뛰고 게임으로" 가는 경로가 애초에 없다.

---

### 3-2. 게임(운동) 진행

```
③-2 게임 진행
├─ 게임 화면 (전체)         물고기 잡기 / 야구 포구
│   └─ FES로 근육이 수축한 그 순간에 잡는 장면이 나온다 (되먹임)
│
├─ 상단 얇은 층
│   ├─ 신호 상태 점 + 문구   연결 좋음 / 센서를 확인해 주세요 / 신호가 끊겼어요
│   └─ 쥔 횟수 알약          "12번 쥐었어요"      ← 이 화면의 유일한 숫자
│
├─ [치료사 보기] 토글  ─→ 하단에서 올라오는 패널
│   ├─ EMG 실시간 그래프    1kHz → 화면 주사율로 다운샘플
│   ├─ RMS                 관찰용. 피로 판정에 쓰지 않는다.
│   ├─ MDF                 관찰용. 피로 판정에 쓰지 않는다.
│   ├─ M-wave 진폭         ★ 피로 판정의 실제 근거
│   ├─ 피로도 상태 색       초록 / 노랑 / 호박
│   └─ FES 자동 제어 상태
│       ├─ 현재 강도 단계
│       └─ 마지막 변경 시각과 이유
│
└─ 하단 조작부 (자기 바탕 위)
    ├─ [자극 조금 줄이기]    세션 중에는 하향만
    └─ [오늘은 여기까지]     1탭. 자극이 가장 먼저 꺼진다.
```

**규칙**

- **환자 기본 화면에는 임상 지표가 없다.** RMS·MDF·그래프는 `치료사 보기`
  뒤에 있고, 이 토글은 세션 요약에 기록된다(누가 언제 열었는지).
- 실시간 그래프가 게임 타이밍을 밀어서는 안 된다(하드 제약 7). 패널이 열려
  있어도 큐 스케줄러는 렌더 루프와 분리된 타이머로 돈다.
- **수축 실패를 연출하지 않는다.** 못 잡은 공은 그냥 지나간다. 빨강·진동·
  실패음 없음.
- 피로 게이지가 32초 안에 30%p 급등하면 피로가 아니라 **"센서를 확인해
  주세요"** 로 분기한다(하드 제약 5).
- 자극 중단의 1차는 **폰의 로컬 자동 종료**다. 원격(웹) 중단은 보조다.

---

### 3-3. 운동 결과

```
③-3 결과
├─ 운동 시간               "9분 18초"
├─ 쥔 횟수                 "340번"
├─ 피로 발생 시점           "6분 12초쯤부터 힘이 줄기 시작했어요"
│                          없으면 → "오늘은 끝까지 힘이 남았어요"
├─ 수행 성공률              "10번 중 8번"       ← 퍼센트 대신 비율 문장
├─ 피드백 메시지            종료 이유별 문구 (아래 표)
│
├─ [치료사 보기] 안에서만
│   ├─ 평균 RMS / MDF
│   ├─ M-wave 진폭 추이
│   ├─ 검출률 · events/burst · 신뢰도 등급
│   └─ 레벨 변화 횟수
│
└─ [마치기]  → 홈
```

**종료 이유별 문구** — 어떤 경우에도 환자 탓으로 들리지 않게.

| 종료 이유 | 문구 |
|---|---|
| 피로 임계 | 오늘 몫을 다 했어요 |
| 성공률 하락 | 오늘은 여기까지가 좋겠어요 |
| 시간 상한 | 오늘 목표를 채웠어요 |
| 사용자 중단 | 잘 마쳤어요 |
| 기기 끊김 | 기기 연결이 끊겨 멈췄어요 |
| 신호 유실 | 센서 신호가 약해져 멈췄어요 |

## 4. 기록 탭

```
③ 기록
├─ 보기 전환   [리스트] [달력]
│
├─ 날짜별 운동 기록 리스트
│   └─ 세션 카드
│       ├─ 날짜 · 시각
│       ├─ 운동 시간 · 쥔 횟수
│       ├─ 신뢰도 등급 뱃지 (A/B/C)
│       └─ 업로드 상태 (동기화됨 / 대기)
│
└─ 세부 기록 보기
    ├─ 그래프 시각화
    │   ├─ M-wave 진폭 변화     ★ 피로 판정의 근거
    │   ├─ RMS 변화             관찰용
    │   ├─ MDF 변화             관찰용
    │   └─ 피로 발생 구간 음영
    │
    ├─ 분석 결과
    │   ├─ 종료 이유 · 최대/종료 피로
    │   ├─ 레벨 변화 횟수 · 검출률 · events/burst 중앙값
    │   └─ 자극 주기 (실측)
    │
    └─ 원시 데이터
        ├─ 버스트 시계열 표
        └─ [CSV 내보내기] · [공유]
```

**규칙**
- 기록 탭은 **치료사·보호자가 보는 화면**이다. 여기서는 지표를 감추지 않는다.
- 다만 **환자 간 절대 피로% 비교와 순위는 만들지 않는다**(하드 제약 6).
  비교는 언제나 같은 환자의 과거 자신하고만 한다.
- 원시 파형(1kHz)은 앱에 저장하지 않는다. 버스트 단위 요약만 남긴다.

## 5. 설정 탭

```
④ 설정
├─ BLE 연결 관리
│   ├─ 기기 스캔 · 연결 · 해제
│   ├─ 마지막 연결 기기 · 자동 재연결
│   └─ 마지막 오류 (원인을 화면에서 지우지 않는다)
│
├─ 기기 설정
│   ├─ 펌웨어 버전
│   ├─ 자극 타임아웃 (펌웨어 값 표시 — 세션 상한이 여기서 유도된다)
│   └─ 영점 보정 (calibrate)
│
├─ 기본 자극 강도
│   └─ 다음 세션이 시작할 단계 (1~10). 세션 중 하향은 여기 저장하지 않는다.
│
├─ 환자 관리
│   └─ 리스트 · 추가 · 수정 · 삭제                → §2 와 같은 화면
│
├─ 앱 정보
│   ├─ 앱 버전 · 펌웨어 호환 버전
│   ├─ 데이터 저장 위치 · 사용량
│   └─ 라이선스
│
└─ (개발) 합성 신호 모드
    └─ 기기 없이 전 구간을 돌려 보는 스위치
```

## 6. TEST 버튼 — 상시 접근, 그러나 게이트는 아니다

AppBar 우측에 항상 있고 **BLE 연결 없이 동작한다.**

```
[TEST]
├─ 화면 확인        게임·손 애니메이션·색·글자 크기
├─ 센서 확인        합성 신호를 흘려 파이프라인이 도는지
├─ 자극기 확인      ← 부착 확인을 통과한 뒤에만 활성
│   └─ 최저 단계 펄스 1회 + M-wave 검출 여부
└─ 진단 정보 복사   버전 · 마지막 오류 · 검출률
```

**핵심: TEST는 게이트 우회로가 아니다.**
자극이 나가지 않는 항목(화면·센서)은 언제나 열려 있지만, **실제 자극을 쏘는
항목은 부착 확인 통과 후에만** 활성된다. 그렇지 않으면 "TEST로 들어가서
전극 없이 자극" 이라는 경로가 생긴다.

## 7. 핵심 UX 규칙 (모든 화면 공통)

| 규칙 | 내용 |
|---|---|
| 큰 버튼 | 주요 버튼 최소 높이 **64pt**. 스펙은 44pt이나 한 손·누운 자세를 고려해 키웠다. |
| 조작부 위치 | 항상 화면 **하단 ⅓** 안. 한 손으로 닿아야 한다. |
| 중단 버튼 | 운동 중 **상시 노출**. 1탭. 확인 대화상자 없음. |
| 숫자 | 환자 화면의 숫자는 **쥔 횟수 하나뿐**. 피로도 퍼센트는 어디에도 없다. |
| 색 | 빨강은 **기기 문제 전용**. 수축 실패에 쓰지 않는다. |
| 실패 | 실패를 연출하지 않는다. 못 잡으면 공이 지나갈 뿐이다. |
| 안정성 | 자극 차단의 1차는 **로컬 자동 종료**. 원격은 언제나 2차. |
| 첫 사용 | 첫 실행부터 게임 시작까지 **3분 이내**. 그래서 고를 것을 늘리지 않는다. |
