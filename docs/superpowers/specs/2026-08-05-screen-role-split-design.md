# 화면 역할 분리 설계안 — 폰은 환자, 웹은 치료사

- 작성일: 2026-08-05
- 브랜치: `feature/screen-role-split`
- 대상: `flutter_app/lib/game/ui/`
- 선행 문서: [2026-08-04-web-monitor-separation-design.md](2026-08-04-web-monitor-separation-design.md)
  — 폰이 서빙하는 관찰 웹(`assets/web/monitor.html`)과 `lib/monitor/` 방송 경로를 그대로 전제한다.

## 1. 목적

관찰 웹은 이미 붙었다. 그런데 폰 게임 화면에도 σ 숫자·존 명칭·예측 배너·존
타임라인이 그대로 남아 있어서, **같은 임상 지표가 두 화면에 중복으로 떠 있다.**

지금 나눈다.

- **폰** — 환자가 보는 것. 게임, 그리고 자기 몸 상태를 한눈에 읽는 스태미나 하나.
- **웹** — 치료사가 판단하는 것. σ, 존, 예측 리드타임, 존 타임라인, RAW 진단.

σ·존·예측은 폰에서 **계속 계산한다.** 자동 휴식 판단과 웹 송신에 필요하기 때문이다.
바뀌는 것은 계산이 아니라 표시다. **이 작업은 계산과 표시를 분리하는 것이 전부다.**

## 2. 왜 지금 중복이 문제인가

세 가지다.

1. 환자가 읽을 수 없는 값이 환자 화면을 차지한다. 완전마비 환자는 σ가 2.4라는 것을
   알아도 할 수 있는 일이 없다 — 수축을 만드는 것은 FES 고, 환자가 더 세게 쥘 방법이
   없다는 것이 이 게임에 판정·점수가 없는 이유와 같다.
2. 화면 면적이 곧 게임이다. 점수가 없는 게임이라 성취감이 전적으로 "공이 글러브에
   들어가는 장면"에서 나온다. 임상 위젯이 코너를 차지할수록 그 장면이 좁아진다.
3. 같은 값을 두 곳에서 그리면 언젠가 갈라진다. 웹은 이미 폰이 계산한 결과를 받아
   그리기만 하므로([선행 문서 §3.1](2026-08-04-web-monitor-separation-design.md)) 값이
   어긋나지는 않지만, 표시 규칙(존 경계 색·반올림·문구)은 각자 관리된다.

## 4. 무엇이 어디로

| 항목 | 지금 | 이후 |
|---|---|---|
| σ 숫자 (`0.2 σ`) | 폰 + 웹 | **웹만** |
| 존 명칭·아이콘 (`✅ 정상`) | 폰 + 웹 | **웹만** |
| 예측 배너 (`⏳ 곧 경고 예상 — 선제 대응 권장`) | 폰 + 웹 | **웹만** |
| σ 다이얼 (`SigmaDial` 62×37) | 폰 | **삭제** — 웹에 반원 게이지가 있다 |
| 존 타임라인 그래프 | 폰 휴식화면 + 웹 | **웹만** |
| 도달 시각·리드타임 (`t1`/`t2`/`t3`) | 폰 휴식화면 (죽은 인자) | **웹만** |
| 근육 스태미나 막대 | 폰 + 웹 | **양쪽 유지** |
| 이닝·포구 수·재생원 라벨 | 폰 | 폰 유지 — 게임 정보다 |
| 무대 존 색 틴트 | 폰 배경 | 폰 유지 |
| 위험 존 비네트 (`_DangerVignette`) | 폰 | 폰 유지 |

### 4.1 스태미나만 남기는 이유

"정지는 사용자 STOP만"이 이 시스템의 원칙이다. 환자가 STOP을 누르려면 근거가 하나는
있어야 한다. 스태미나는 그 근거로 유일하게 적합하다 — **`100 − z/4×100` %** 이고,
100%가 언제나 그 사람 **자신의 초기 상태**이지 집단 평균이 아니다(SPC 자기기준 원칙).
"내 여력이 줄고 있다"는 환자가 읽고 행동할 수 있는 문장이다.

### 4.2 색은 남기고 숫자와 명칭은 뺀다

무대 틴트·위험 비네트·스태미나 막대 채움색은 존 색을 그대로 쓴다. 색은 분위기이지
판독값이 아니다. 환자가 색을 보고 "빨개졌네"라고 느끼는 것과 "2.4σ, 경고 존"을 읽는
것은 다른 일이다. 전자는 남기고 후자는 웹으로 보낸다.

## 5. 컴포넌트 변경

### 5.1 신설

**`lib/game/ui/widgets/patient_status_card.dart` — `PatientStatusCard`**

스태미나 막대 하나만 담는 카드. 지금 `FatiguePanel` 이 있던 우상단 자리에 들어간다.
`sigma` 하나만 받는다.

별도 위젯으로 만드는 이유: 게임 화면이 "환자용 위젯"만 임포트하게 되어 경계가 코드로
드러난다. `StaminaBar` 를 `game_screen.dart` 에서 직접 감싸면 경계가 화면 파일 안에
녹아 사라진다.

## 6. 데이터 흐름 — 바뀌지 않는다

```
LiveFatigueFeed ─┬─▶ BaseballGame   ──▶ PatientStatusCard   (스태미나만)
                 ├─▶ RestPolicy     ──▶ 자동 휴식            (σ·예측 그대로)
                 └─▶ MonitorSource  ──▶ 웹                   (σ·존·예측 전부)
```

σ 계산(`SigmaTracker`), 휴식 판단(`RestPolicy`), 모니터 송신(`MonitorSource`) 은 한 줄도
바뀌지 않는다. 잘리는 것은 위젯 트리뿐이다. 이 점이 이 변경의 위험을 낮춘다 —
신호 파이프라인에 손을 대지 않으므로 σ 값이 달라질 경로가 없다.

## 7. 경계를 지키는 방법

삭제만 하면 다음 사람이 다시 얹는다. §3에서 뒤집는 결정이 원래 명시적으로 적혀
있었다는 사실 자체가 그 증거다. 테스트로 못박는다.

판정은 **렌더된 `Text` 위젯의 문자열**로만 한다. 색(무대 틴트·위험 비네트·스태미나
채움)은 판정 대상이 아니다 — §4.2 에서 남기기로 한 것들이고, `_DangerVignette` 는
그라디언트뿐이라 애초에 문자열을 만들지 않는다.

| 대상 | 방법 |
|---|---|
| 게임 화면 경계 | 위젯 — 게임 화면 트리의 어떤 `Text` 도 `σ` 를 포함하지 않고, 존 명칭(`정상`/`주의`/`경고`/`위험`)과 일치하지 않는다 |
| 휴식 화면 경계 | 위젯 — 휴식 오버레이를 띄운 트리에 같은 조건 |
| 스태미나는 남는다 | 위젯 — 게임 화면에 `근육 스태미나` 텍스트와 `%` 로 끝나는 텍스트가 **있다**. 경계 테스트가 "전부 지우기"로도 통과되지 않게 막는 반대편 핀 |
| 휴식 판단 유지 | 기존 테스트 — σ 임계 도달 시 여전히 자동 휴식이 걸린다 |
| 웹 송신 유지 | 기존 테스트 — `MonitorSource` 가 σ·존·예측을 그대로 내보낸다 |

기존 [`game_screen_layout_test.dart`](../../../flutter_app/test/game/game_screen_layout_test.dart)
에 붙인다. 이 파일에는 지금 쓰이지 않는 `glovePlateRatio` 상수(값 0.80, 실제 코드는
0.82)가 남아 있다 — 손대는 김에 정리한다.

## 8. 받아들이는 위험

**치료사가 웹을 보지 않는 시간에는 σ를 아무도 보지 않는다.**

지금까지는 "폰 화면 + 자동 휴식" 이중 안전망이었다. 이후에는 자동 휴식(`RestPolicy`,
현재 σ와 예측 σ 중 나쁜 쪽 기준)이 **단독 안전망**이 된다.

이것을 받아들이는 근거는 둘이다.

1. 폰 화면은 애초에 안전망으로 설계된 적이 없다. 환자가 σ를 보고 멈추리라는 가정은
   검증된 바 없고, 대상이 완전마비 환자라 "보고 조절한다"는 경로 자체가 약하다.
2. 자동 휴식은 예측 σ까지 보고 선제적으로 건다. 사람이 화면을 지켜보다 반응하는
   것보다 빠르다.

받아들이지 못할 상황이 생기면 폰에 존 색 배너 하나를 되살리는 것이 가장 싼 복구책이다
(숫자 없이 색과 문구만).
